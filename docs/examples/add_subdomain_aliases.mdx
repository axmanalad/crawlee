The `subdomainAliases` parameter in <ApiLink to="core/function/enqueueLinks">`enqueueLinks()`</ApiLink> allows you to specify which subdomains should be allowed when filtering URLs for enqueuing. For example, allow both `example.com` and `www.example.com` links to pass through the same-hostname filter.

By default, `subdomainAliases: ['www']` allows both the main domain and www subdomain to be enqueued.

:::info

This only affects URL filtering (which URLs are allowed to be enqueued), not deduplication. Both `example.com/page` and `www.example.com/page` would still be enqueued as separate requests. Works with `SameHostname` strategy only (not with `SameOrigin` which requires exact hostname matching).

:::

## Configuration

```javascript
// Default - www subdomain alias
await enqueueLinks({
    subdomainAliases: ['www'] // This is the default
});

// Multiple aliases
await enqueueLinks({
    subdomainAliases: ['www', 'blog', 'support']
});

// No aliases - strict matching
await enqueueLinks({
    subdomainAliases: []
});

// Note: SameOrigin strategy does not use subdomainAliases
// It requires exact hostname and protocol matching
await enqueueLinks({
    strategy: EnqueueStrategy.SameOrigin
    // subdomainAliases is ignored for SameOrigin
});
```
